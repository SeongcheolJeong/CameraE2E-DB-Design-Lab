개발 촬영을 등록한 뒤 실물 카메라와 대응 DB 모델을 고정합니다.

DB 모델의 pixel pitch·CFA·ADC·D65·조리개·gain·온도가 촬영 선언과 맞아야 합니다.

DB 4채널 native PSF·센서 ADC를 실제 MTF 예측에 사용합니다. DB 가상 탐침을 센서 모서리로 자동 환산하지 않습니다. 절대 색·Tone·조도·노이즈 및 제조사 ISP의 완전한 재현에는 추가 모델 입력이 필요합니다. 보정 후는 조건부 유효 응답 후보이며 자동 활성화하지 않습니다.

OPTIONAL IQ · NOMINAL REFERENCE

색·계조·노이즈 평가 추가

명목 reference ID와 hash는 서버에서 고정합니다.

sRGB transfer encoding과 sRGB 색 공간은 다릅니다. 미확인 상태에서는 실제 ISP의 절대 색차를 계산하지 않습니다. 명목 기준과 reference ISP의 색차도 절대 색 정확도 합격이 아닌 진단입니다. 18 color + 20 gray ROI를 매 촬영에서 확인해야 합니다.

기본 3쌍으로 반복 노이즈를 계산합니다. 추가 0–5쌍을 입력하면 총 3–8프레임이며 8프레임을 권장합니다. 추가 ID는 기본 3개와 겹치지 않아야 합니다. 새 검증도 개발과 같은 추가 수를 유지합니다. 역할과 고정 조건을 섞지 않으며 공간 분산을 센서 PTC·DR로 바꾸지 않습니다.

후보와 판정 범위

CCM은 reference ISP 후보입니다. 실제 제조사 ISP를 덮어쓰지 않습니다. IQ 판정은 기준 미선언으로 보류하며, 동일 RAW의 baseline/reference CCM 출력과 실제 ISP 관측을 나란히 보존합니다.

RAW·ISP 쌍 업로드

개발 촬영

먼저 개발 촬영 3쌍을 등록합니다. 검증 촬영은 후보가 고정된 뒤 새 세션에서 취득하세요.

현재 DB 보정 연결: RGGB Bayer 원본과 같은 native raster의 ISP. DNG/CR2/CR3/NEF/ARW/YUV, binning·resize·회전·mirror, unknown ISP transfer는 이 경로에서 지원하지 않습니다. 다른 형식을 지원 형식으로 허위 선언하지 마세요.

null은 직접 확인해 입력할 값입니다. conditions에는 고정 설정·기준 온도를, capture_observations에는 촬영별 실제 조도·온도를 기록합니다. session_id는 개발·검증을 구분하고 captured_at은 실제 노출 시각으로 입력합니다. 검증 양식에는 고정 계약에서 확인된 설정과 계약 ID/hash를 복사하며, 취득 확인 항목은 직접 작성합니다.

03 / CANDIDATE THEN NEW ACQUISITION

선택과 검토가 끝나면 단계별로 실행합니다.

개발 RAW Gr SFR만으로 camera-effective 공간응답을 보정합니다. ISP는 별도 진단이며 처리 파이프라인이 일치한다고 입증된 경우에만 대응 기준으로 판단합니다. 순수 렌즈 PSF 복원이나 ISO 적합성 인증은 아닙니다.

검증 단계에서는 후보를 다시 피팅하지 않습니다. 실패한 검증도 원본과 보고서에 남으며 활성 모델 변경 여부는 결과에서 명확히 확인합니다.
