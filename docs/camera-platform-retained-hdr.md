# 잔류 PD 상태를 고려한 다중 노출 HDR · 0.16.1.dev21

개발 소스의 `retained_stateful_hdr`는 **명시적으로 선택하는** 다중 노출 경로다. 동일한 정적 장면과 일정하거나 정확히 작성된 PWM 광원, trap 없는 PD 잔류 모델, 단일 선형 전기 readout, 전체 native 센서에서만 실행한다. 각 프레임의 실제 적용 노출은 제어 시퀀스에 고정한다. 원본 정수 RAW와 전하 사건·시간·출처를 보존한다.

각 RAW를 작성한 전기 모델로 **전달 총전하**에 역변환한다. 이전 프레임에서 추정한 잔류 전하, 노출 간격 및 현재 노출의 암전류를 순서대로 빼고, CFA 사이트별 부분 이동 효율을 역산해 **현재 노출에 생성된 광전자율**을 추정한다. 알고리즘에는 시뮬레이터의 내부 전하 진실 배열을 주입하지 않는다. 포화·불명 상태는 무효로 두고, 불명 잔류 상태는 선언된 PD clear가 있을 때까지 전파한다. 여러 유효 노출이 서로 맞지 않으면 해당 픽셀을 무효로 둔다. 맞는 경우 가장 긴 유효 노출을 선택한다. 표시 RGB는 이 광전자율의 진단용 preview이며 원본 RAW의 코드 영역 ISP 결과와 별개다.

이 수치는 **작성 모델을 조건으로 한 PRNU 포함 광전자율**이다. 장면의 물리 복사휘도나 실측 교정된 HDR은 아니다. 전기 gain·암전류·이동 효율은 추정 입력이며 총 예측 불확실도는 `unknown`이다. 일치성 판정은 상관 잡음까지 증명하는 통계 검정이 아니고, read noise에 숨은 포화의 부재도 증명하지 않는다. 움직임, trap 포획·방출, HCG/LCG 경로 결합, 비선형 readout, 임의의 초기 전하, 전체 센서 밖 크롭은 거부한다. LFM 성공이나 움직임 정합을 주장하지 않는다.

`dev21`은 PWM의 정확한 row별 광량 적분을 **광전하율의 분모**로 사용한다. 암전하는 PWM의 꺼진 구간에도 생성되므로 실제 전체 노출 시간과 프레임 간격으로 별도 차감한다. 광적분이 0인 row에서는 광전자율을 무효로 두되, RAW에서 판독 가능한 잔류 상태는 다음 프레임으로 전달한다. 여러 노출의 선택 기준도 실제 광적분 시간이다. RAW, 작성 파형, 실제 row 시간만 HDR 역산에 사용하며 시뮬레이터의 내부 전하 배열은 쓰지 않는다. 이는 작성한 PWM/시계가 정확하다는 **모델 조건부 계산**이고 측정 LED 파형·시계 오차·실물 LFM 성능 증거는 아니다. 독립 row ON 구간 계산과 실제 Runtime 연결 검사가 통과했다.

`dev22`에는 작성한 분광 광입력·생성 응답·전하 수집에서 행별 PWM와 잔류 PD를 거쳐
정수 RAW와 RAW 전용 HDR까지 가는 독립 스칼라 수지 검사를 추가했다. 생성/수집
전하의 oracle은 결과 분석에만 사용하고 합성 알고리즘에 주입하지 않는다. 이 검사는
모델 단계의 연결·단위 확인이며 실물 LED/PD/전기 보정이나 trap 결합 HDR 검증은 아니다.

합성 2/8 ms·4프레임 사례를 별도 API/Worker에서 실행하고, 저장 RAW SHA·HDR 배열·원본 RAW를 사용하는 code ISP replay·ZIP 해시를 검사했다. QA용 내부 진실 배열과 사후 비교한 유효 프레임 광전하 오차 최대값은 **3.61 e**였다. 이 비교 배열은 HDR 계산 입력이 아니며 실제 센서 정확도 근거도 아니다. 장노출 포화 시 짧은 노출 선택, 불명 상태의 전파/clear, 프레임 간 광량 불일치 거부는 별도 합성 단위 테스트로 확인했다. 관련 Python **203개**, Node UI **311개**, 실제 Worker **2건**, HTTP 최초 **134개**·재시작 **136개** 검사가 통과했다. 브라우저에서 HDR 출력과 템플릿을 확인했으며 오류는 0건이었다. 두 QA 서버/Worker는 종료했고 원래 앱의 행·PID는 그대로다.
