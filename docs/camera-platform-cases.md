# Engineering case reviews · v0.15 candidate

사례의 설계 질문, 요구사항과 고정 시험, 검토할 카메라 구성, 선택한 근거, 판단 이유,
남은 문제, 다음 실험 계획을 하나의 불변 리뷰로 저장합니다. 이 문서는 개발 중인
v0.15의 계약을 설명합니다. 기본 작업실의 설치 버전은 인도 기록 `delivery.json`으로
확인해야 하며, 소스 버전 변경만으로 설치 버전이 바뀌지는 않습니다.

## 사용 흐름

1. 사례 개요에서 새 사례를 만들고 설계 질문과 현재 판단 이유를 입력합니다.
2. 필요한 요구사항과 Registry의 고정 시험·카메라 구성을 선택합니다.
3. 관련 실행·관측·검증·설계 탐색 기록만 근거로 연결합니다. 근거마다 해당 요구사항을
   지정합니다. 실행은 완료·실패·취소 상태여야 하고, 실제 시험 조건이 고정 시험과
   같아야 합니다. 실험 중 노출을 덮어쓴 결과는 새 시험을 고정해 실행해야 합니다.
4. 남은 문제와 다음 실험의 질문·이유·방식·조건을 기록하고 저장합니다.
5. 판단이 바뀌면 새 리뷰를 작성합니다. 이전 리뷰는 원본대로 유지되며 이력에서 열거나
   JSON으로 내보낼 수 있습니다. 동시에 다른 리뷰가 저장되면 최신 리뷰를 확인한 뒤
   다시 작성해야 합니다.

시험과 근거가 없는 초기 사례도 저장할 수 있습니다. 근거를 붙일 때는 해당 요구사항에
시험을 지정해야 합니다. 작업실의 다른 실행이나 PASS 결과는 사례의 판단을 바꾸지
않습니다. 다음 실험 계획을 저장하는 것만으로 계산이나 장비 수집이 시작되지는 않습니다.

## 근거의 의미

서버는 카메라·시험 연결을 확인하고 결과 전체를 해시와 함께 고정합니다. 작업 요청 해시와
계산 결과 해시는 구분됩니다. 선택한 실행의 입력·출력 파일, 관측 원본 및 연결된 RAW와
분석 이력은 실제 파일 해시를 검사합니다. 조회할 때도 연결 관계와 파일 무결성을 다시
확인하므로 원본 파일이 삭제되거나 손상되면 정상 근거로 표시하지 않습니다.

한 사례의 원본이 없거나 손상돼도 다른 사례와 작업실 메뉴는 계속 사용할 수 있습니다.
목록에서는 해당 사례를 `camera_case_review_unavailable_v1` 요약으로 반환하고 “근거 확인
불가”로 표시합니다. 이 요약에는 판단·근거 스냅샷·정상 결과 해시가 없습니다. 정확한 리뷰
상세는 계속 거부하며, 같은 원본 바이트를 복구하면 원래 리뷰를 다시 확인할 수 있습니다.
목록의 정상 사례는 기존 전체 리뷰 계약을 유지합니다. SDK 호출자는 항목의 `schema`와
`availability`를 확인해야 합니다. Registry 기록 자체의 무결성 오류는 별도입니다.

보정 카메라와 원래 관측 카메라가 다른 검증은 기존 보정 동등성 및 계보 검사를 통과하고
양쪽 카메라가 사례에 포함될 때만 연결할 수 있습니다. 임의의 다른 카메라 결과는
거부합니다. 설계 탐색은 기준 시험·구성과 개별 후보 실행의 연결을 함께 보존합니다.

`open`, `investigate`, `candidate`, `rejected`, `deferred`는 사용자가 남긴 설계 판단입니다.
어떤 값도 실물 검증이나 출시 승인 권한을 부여하지 않습니다. 합성 관측은 실물 측정으로
바뀌지 않습니다. 현재 독립 실물 카메라 검증과 총 예측 불확실도는 미확립 상태입니다.

## API와 SDK

| 동작 | API | Python SDK |
| --- | --- | --- |
| 첫 사례 또는 새 리뷰 저장 | `POST /api/v1/case_reviews` | `create_case_review(payload)` |
| 사례별 최신 리뷰 | `GET /api/v1/case_reviews` | `list_case_reviews()` |
| 정확한 리뷰 열기 | `GET /api/v1/case_reviews/{id}` | `get_case_review(id)` |
| 사례의 모든 리뷰 | `GET /api/v1/case_reviews/{id}/history` | `case_review_history(id)` |

저장에는 세션 토큰과 안정적인 `request_id`가 필요합니다. 같은 요청은 같은 리뷰를 반환하고
추가 이력을 만들지 않습니다. 같은 식별자를 다른 내용에 재사용하면 409입니다. 새 리뷰에는
현재 최신 리뷰의 `previous_revision_id`를 지정합니다. 브라우저는 초안과 응답이 불확실한
저장 요청을 탭의 세션 저장소에 보존합니다. 이는 다른 브라우저나 기기 간 초안 동기화가
아니며, 완전히 닫은 탭의 미저장 초안 복구를 보장하지 않습니다.

작업실 목록에는 작은 요약을 보내며 원본은 상세 조회로 엽니다. JSON 내보내기는 리뷰와
근거 스냅샷을 포함하지만 참조된 모든 RAW 파일을 넣은 독립 실행 패키지는 아닙니다.
Agent 자동 계획·실행, 역할별 승인, 고객 다중 사용자 운영은 후속 범위입니다.
