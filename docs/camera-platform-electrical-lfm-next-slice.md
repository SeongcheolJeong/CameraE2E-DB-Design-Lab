# 다음 범위: 전기 AE와 고정 노출의 관측 비교

> 보존된 설계 제안. 후속 개발판의 실제 제공 계약은
> [전기 RAW 응답 비교](camera-platform-electrical-response.md)를 따른다.
> 아래의 미구현 표기는 제안 작성 당시의 상태이며, 설치본 승격을 뜻하지 않는다.

2026-09-24의 **제한된 미구현 제안**이다. 현재 제공되는 경로는
[전달 RAW를 관측하는 전기 모델 노출 AE](camera-platform-electrical-control.md)이며,
이 문서는 그 결과를 고정 노출 기준선과 비교하고 PWM·지연 조건에서 평가하는 다음
범위를 제안한다. 새 비교 작업·평가 지표·화면이 이미 구현되었다는 뜻이 아니다.
설치본과 기본 앱의 버전, 실제 검증 결과는 별도 개발 인도 기록을 따른다.

원문의 **Asset Registry, Model Factory, Camera Composer, Simulation Runtime,
Validation Center, Experiment & Optimization, Agent & Release Control** 일곱 모듈과
**Quick Estimate, Response-DB Simulation, Surrogate Prediction,
Detailed Characterization** 네 실행 방식을 유지한다. 이번 제안은 일반 광학·픽셀·전기,
HDR/LFM, 고급 ISP·최적화라는 목표 중 전기 관측과 실험 판정의 연결에 해당한다.
새 실행 방식이나 모든 기존 방식에서의 기능 지원을 선언하지 않는다.

## 먼저 해결할 문제

현재 AE는 실제 적용 노출로 PWM·장면 적분, 잔류 PD 전이와 전기 readout을 수행한다.
그러나 `target_outcome`은 유한 관측열의 목표 구간 진입 횟수와 끝부분의 연속 관측을
기록할 뿐, 선언된 변화 시점과 평가 구간이 없어 settling을 정의하지 않는다.
일반 RAW 실측 비교기도 `closed_loop_comparison_operator_required`로 거부한다.
초기 노출을 모든 프레임에 적용한 것처럼 취급하면 이 빈칸을 채울 수 없다.

다음 질문은 “동일한 센서·장면·초기 상태에서, 고정 노출과 RAW 기반 AE가 어떤
관측 응답과 명령 지연을 만들며, 선언한 코드 목표를 어느 구간에서 만족하는가?”다.
PWM에서는 위상과 지연에 따른 관측 차이를 별도로 본다. 시간 변화가 작아졌다는
사실만으로 LED flicker mitigation 개선이나 신호 보존을 주장하지 않는다.

## 첫 범위와 동결 입력

첫 범위는 현행 `electrical_control_v1`의 full-native RGGB, 단일 선형 또는 비선형
전기 readout, 최대 16프레임과 노출 전용 정책이다. Gain·WB·ISP·readout 선택·PD clear
목록은 고정한다. DCG 경로 선택, gain 제어, AWB, HDR 합성, PWM 위상 추정, motion
보상은 포함하지 않는다. 기존 프레임·메모리·증거 상한을 늘리기 위한 작업도 아니다.

하나의 비교 계획은 다음을 immutable ID와 내용 해시로 동결한다.

- Camera Assembly와 광학·픽셀·전기·PD 모델, native geometry와 RAW 형식.
- 시간 장면, 원래 clock, frame IDs·starts·shutter mode와 균일한 초기 설정.
- 기준 정책, 평가 ROI·native 사이트, 목표 DN 구간, 평가 구간·유지 조건.
- PD clear 목록, 초기 상태 계약, noise 모드와 명시적인 seed 목록.
- 실험 축, 각 축의 유한 값 목록, 후보 순서, 전체 실행 수와 자원 예산.

각 실험 조건마다 같은 동결 입력으로 **고정 기준선과 AE 후보**를 구성한다.
고정 기준선도 `electrical_control_v1`을 사용하되 정책 `enabled=false`로 초기 노출을
유지한다. 기존 stateless 캡처를 기준선으로 대체하지 않는다. 각 실행은 각 행의 첫
노출 시작에서 빈 PD와 별도의 난수 세션으로 시작하며, 두 실행 사이에 reservoir를
공유하지 않는다. 고정 설정과 AE의 실제 적용 노출 차이는 실험 결과다.

동일 seed는 입력 난수 정책이 같다는 의미다. 서로 다른 노출에서는 분포와 난수 소비가
달라질 수 있으므로 픽셀별 잡음 표본의 일대일 대응을 보장하지 않는다. 먼저 noise를
끈 결정론적 흐름으로 관측·명령·RAW 차이를 확인하고, 확률 실행은 seed별 결과와
분포를 별도로 남긴다. 결정론적 포화 결과를 확률 모델의 기댓값으로 부르지 않는다.

## 관측 연산자와 평가 구간

평가 입력은 선택한 단일 경로의 원본 integer RAW, 실제 획득 조건·행별 시각,
명령 추적과 동결된 평가 명세다. 정책의 meter와 별개로 평가 ROI·사이트도 계획에
명시한다. 정책 후보가 meter를 바꾸더라도 평가 대상을 몰래 바꿀 수 없어야 한다.

관측량은 signed black-relative DN이다. 정수 코드 합과 표본 수, 선언한 black level,
full-native CFA 위상을 보존한다. 음수·rail 표본을 제외하지 않는다. Exposure로
나누거나 비선형 곡선을 역산해 현재 광전하·장면 휘도로 바꾸지 않는다. 관측 digital
rail 비율과 시뮬레이터 PD overflow는 다른 양으로 남긴다.

평가 구간은 실행 전에 원래 scene clock의 시작·끝, 작성자가 선언한 변화 시점,
순서가 있는 공통 frame ID 목록, 목표 구간과 유지 조건을 정한다. Frame ID가 같아도
두 실행의 노출 종료와 `statistics_ready_ns`는 달라질 수 있다. 프레임 대응은 ID로,
응답 지연은 각 실행의 실제 시각으로 계산하며 두 시간축을 혼합하지 않는다.
Rolling shutter에서는 변화 시점을 가로지르는 행별 적분 구간도 표시한다.

선언된 정상광 step 구간에서만 다음을 정의한다.

- 프레임별 목표 구간 안/밖, 상한 초과 DN, 하한 미달 DN과 digital rail 비율.
- 필요한 연속 관측 수와 최소 관측 span을 모두 만족하는 첫 구간. Span은 첫 관측과
  마지막 관측의 `statistics_ready_ns` 차이다. 그 사이의 모든 선택 관측을 검사한다.
- 변화 시점부터 해당 구간 첫 관측이 준비된 시점까지의 지연과, 유지 조건 확인 시점까지의
  지연을 각각 기록한다. 확인 시각을 진입 시각으로 소급해 숨기지 않는다.
- 완전한 평가 구간 안에서 조건을 충족하지 못한 `not_reached`, 필요한 후속 관측이나
  구간이 부족한 `censored`, 정의가 맞지 않는 `not_applicable`을 구별한다.

선택 관측 사이를 보간해 연속 신호의 유지나 제어 안정성을 보증하지 않는다. 구간 시작을
가로지르는 적분 표본의 포함 규칙도 미리 정하고 결과와 함께 보존한다. 같은 목표를
만족하는 여러 후보를 단일 수렴 점수로 합치지 않는다. PWM 구간에는 정상광 settling을
자동 적용하지 않으며, 선언한 frame별 코드·rail·목표 이탈의 관측열을 우선 제공한다.

## PWM 위상·지연 실험과 제한된 탐색

첫 비교 계획은 작성자가 고른 유한 격자만 지원하는 것이 적절하다. 예를 들어 PWM
phase offset과 하나의 제어 지연을 두 축으로 선택하고, 다른 값은 고정한다. 이후 정책
배율 또는 노출 grid를 탐색할 때도 축·값·비교 기준을 계획에 명시한다. 위상과 지연,
정책을 동시에 무제한 조합하거나 자동으로 다음 실험을 추가하지 않는다.

제안 상한은 **최대 두 축, 전체 조건·정책·seed 조합 12개**다. 각 조합의 고정/AE
실행을 포함해 최대 24개 캡처이며, 이를 계산 비용으로 제출 전에 표시한다. 기존
16프레임 한도에서 유지 조건을 확인할 수 없는 명세는 프레임 수를 자동 확대하지 않고
계획에서 거부하거나 불완전한 관측 범위를 명시해야 한다. 이 상한과 최종 schema·API
이름은 구현 검토에서 확정하며 현재의 제공 계약으로 간주하지 않는다.

PWM 위상은 합성 장면의 작성 조건이므로 실험과 독립 oracle은 알 수 있다. 제어기에는
넘기지 않는다. 서로 다른 위상의 결과는 각 조건 안에서 기준선과 먼저 비교하고,
위상별 원본 관측을 남긴다. 모든 위상을 평균해 실패 조건을 숨기지 않는다.
Raw 변화량 감소, 목표 구간 진입, clipping 감소에는 각각 이득과 손실이 있을 수 있으므로
개별 결과를 제공한다. **포괄적인 LFM 점수·실물 PASS·자동 최적 모델 승격은 없다.**

## Registry·Test·Worker·증거 연결

아래는 새 비교 기능이 충족해야 할 제안 흐름이며, 이미 존재하는 endpoint 목록이 아니다.

1. 계획 단계에서 동결 source와 모든 실험 변형을 검증하고 plan hash, 실행 수,
   예상 배열·trace·bundle 크기를 만든다. PWM 변경은 새 프로그램 변형으로, 지연·정책
   변경은 새 정책 변형으로 표현한다. 원래 등록 기록을 덮어쓰지 않는다.
2. 각 baseline/candidate에 맞는 Capture Program과 Test를 별도 고정한다. 입력 Test의
   `frame_conditions=null`과 초기 scaffold 의미를 유지하며, 실현된 노출은 실행 후
   acquisition 계약으로 보존한다. 다른 Test를 같은 조건인 것처럼 재사용하지 않는다.
3. 확인된 계획으로 durable 비교 작업과 그에 속한 캡처 작업을 연결한다. Child는 기존
   Runtime·Worker 경로로 실행하고, 비교기는 검증된 child RAW/실현 계약만 읽는다.
   비교용 evaluator에 전체 simulation result나 숨은 ledger를 그대로 전달하지 않는다.
4. Worker는 실행 직전 Registry 원본·프로그램 blobs·Test·계획 해시·환경을 재검증한다.
   Child의 성공 상태만으로 결과를 신뢰하지 않고 RAW hash, 출력 shape와 frame/source
   연결까지 검사한다. Cache는 완전히 같은 동결 입력에만 적용하고 reused 실행 ID를 남긴다.
5. 취소·timeout·실패·일부 성공을 구분한다. 비교 취소는 그 계획이 소유한 미완료 child에
   전달하고 다른 작업을 중단하지 않는다. 실패한 조건을 버리거나 불확실한 제출을 자동
   반복하지 않는다. 재실행은 새 시도 ID와 처음부터의 PD 세션으로 남긴다.
6. UI는 각 조건의 고정/AE 결과, 실제 적용 노출, 관측 시각, 명령 판정, 구간별 평가와
   미도달/미관측 사유를 나란히 보여준다. Noise 모드와 실제 readout 형식을 유지한다.
7. Export와 bundle은 계획, 원본·정규화 프로그램, Test·장면·모델의 입력 closure,
   각 실행 요청·환경·RAW·추적·평가 결과와 해시를 포함한다. 재시작 후 GET-only 검증으로
   같은 연결과 bytes를 확인한다. 불완전 실행도 상태와 남은 근거를 보존한다.

합성 전하·입사 광량·PWM 작성값은 `synthesis_diagnostics`와 같은 명확한 별도 역할로
보존할 수 있다. 이 자료는 모델 계산 확인용이며 controller/evaluator의 RAW 관측 입력이나
독립 실측이 아니다. 물리 실측의 시간 동기·readout·실현 제어를 연결하는 미래 비교기는
별도 계약이 필요하다. 이번 제안으로 기존 정적 비교기의 거부 조건을 해제하지 않는다.

## 의미 있는 독립 검증과 완료 조건

- 작은 native 격자에서 정수 ns PWM ON 구간과 각 행의 실제 노출 구간의 교집합을
  독립적으로 열거한다. 적용 노출 전후의 photon 입력, PD 보존식과 별도 scalar 선형/
  비선형 encoder로 원본 RAW를 검산한다. 이 oracle의 합성 truth는 제품 평가 입력이 아니다.
- 작은 수동 RAW 열과 유리수 black level로 ROI/CFA 합계, 음수값, rail 비율과 평가 구간
  결과를 직접 계산한다. 제품의 meter나 metric 함수를 기대값 계산에 재사용하지 않는다.
- 정확한 latch tie, 최소 프레임 지연, 늦게 도착한 옛 명령, 마지막까지 미적용된 명령을
  검증한다. 미래 장면·RAW·ledger를 바꾸어도 이미 완료된 관측과 제안은 바뀌지 않아야 한다.
- 고정/AE가 같은 노출을 적용하는 조건에서는 같은 입력으로 동일한 RAW가 나오는지,
  실제 노출이 달라지는 조건에서는 그 변화가 latch 이후의 적분·RAW에 반영되는지 확인한다.
  정책 상태만 바꾸고 기존 RAW에 배율을 곱한 구현을 검출해야 한다.
- 완전한 PWM 주기와 비정수 주기 노출, phase shift, rolling 행 위상, 밝음→어둠과 잔류
  전하를 포함한다. 동일 현재 광량이어도 이력 때문에 다른 전달 코드가 나올 수 있음을 확인한다.
  교대 응답·clipped 상수 신호를 좋은 settling 또는 LFM 개선으로 오판하는 반례를 넣는다.
- 선언 구간 밖 표본, 누락된 후속 관측, 유지 조건 경계, 목표 미도달을 구분한다. 확률 조건은
  결정론 oracle과 분리해 보존하고 같은 seed의 서로 다른 노출을 표본별 동치로 검사하지 않는다.
- 원본·Test·계획·RAW 변조, cached 실행 연결 변조, 취소·timeout·restart·bundle 누락을
  실제 서비스 경로에서 검사한다. 실제 UI의 계획→제출→조건별 비교→원본 export를 별도로 확인한다.

독립 수치 검산, 서비스/Worker 연결, 실제 UI와 재시작 증거가 모두 준비되어야 이 제한된
범위를 완료로 기록한다. 시험 수만으로 물리 정확도나 전체 제품 진행률을 올리지 않는다.

## 뒤따르는 확장

다음 단계는 고정 HCG 또는 LCG 관측의 AE, 실현된 AE RAW를 받는 code-domain ISP
source 계약, 독립 reference를 둔 ISP·정책 비교다. 상태 이력을 포함한 HDR fusion은
별도의 신호/관측 모델이 필요하다. 기존 HDR의 독립 reset·정적 장면·whole-period PWM
제약을 제거하는 방식으로 연결하지 않는다.

일반 광학의 유한 물체 거리·깊이와 sensor plane 연계, 픽셀 수집/잔류 전하의 조건별
파라미터 식별, trapping/release·CDS 등의 전기 확장은 병행 우선순위로 남긴다.
독립 실측과 불확실도 없이 물리 AE 안정성, 실제 센서 지연, 상용 HDR/LFM 성능을
인증하지 않는다. 이 비교 기능의 완료가 일곱 모듈·네 실행 방식의 상용화 완료는 아니다.
