# Anchored nonlinear response fitting — dev13 implementation contract

Status: bounded dev13 capability verified. Fixed-condition nonlinear response/noise fitting, explicit publication and imported RAW replay are connected through API/SDK/Worker/Workbench. This is authored numerical and software-path qualification, not physical camera validation. The original seven modules and four execution modes and the optics/pixel/electrical, HDR/LFM and advanced ISP/optimization priorities remain active.

## Numerical meaning

Fit a fixed native sensor's memoryless charge-to-voltage response and marginal conversion-output Gaussian read-noise scale from registered RAW and independently anchored **total pre-full-well Poisson charge means**, including dark. The target mean is not inferred from RAW or exposure. Do not add the supplied dark-rate map to these total means again. Preserve the base dark map, ADC/black/gains, capacities and charge-knot positions. Estimate positive voltage increments and positive marginal noise scales within explicit bounds. Response and noise domains are fixed to the observed training temperature and path gains; exposure applicability remains within the base domain and the training exposure range.

Use the exact finite Poisson support up to each effective capacity, with the upper tail lumped at the clipped capacity. The observed RAW bin probability uses the two actual nearest-even ADC/digital quantizers, including half-infinite endpoint bins and impossible final codes. No DN midpoint regression or additive quantization-noise variance is substituted. Limit total samples, groups, knots and finite-support/bin work before queue admission. These are implementation budgets, not physical validity domains.

Numerical evaluation uses float64 Poisson masses and stable Gaussian log-CDF differences, with eight-point quadrature for very short intervals. The support is complete; numerical arithmetic is not exact real arithmetic. Positive response increments and log noise sigma are fitted with bounded L-BFGS-B and analytic gradients. Report convergence, gradient and bound contacts; convergence does not prove a global optimum or statistical identifiability. Code diagnostics include the observed mean, observed and predictive medians, marginal likelihood and discrete predictive coverage. Predictive means are explicitly unavailable rather than approximated by transforming the expected input.

Each training/evaluation pool admits at most 8,192 RAW codes and 128 distinct exact input means. Paired path codes count toward the resource budget while acquisition/site row counts remain separate. Effective capacity is at most 65,536 electrons and each fixed curve has at most eight knots. The admitted likelihood/CDF work is bounded, and worker output/portable graph sizes have separate hard limits. Training requires varied low-charge repetitions, levels inside every fitted segment and a conditioned response design; sparse or fully censored data is refused.

Sequential input uses one marginal likelihood. DCG uses a sum of two marginal likelihoods of the same acquisition: it is a composite objective, not a joint likelihood and not twice as many independent acquisitions. Inherit the base correlation coefficient and apply it to the fitted marginal scales; record this as an unestimated correlation assumption. Joint covariance fitting and joint coverage remain open.

At a perfectly correlated boundary, binary64 cross-covariance can require rounding toward zero to remain positive semidefinite for the declared diagonal values. The bounded ULP adjustment is recorded explicitly; no jitter is added and correlation is not estimated. A zero base variance makes inherited correlation undefined, so paired fitting refuses it; numerical evaluation still supports degenerate zero noise.

Separate training and held-out acquisition lineage. Held-out codes are evaluated only after the candidate parameters are frozen. Report code residuals, marginal negative log likelihood and central predictive coverage, optimizer convergence/bound contacts, support limits and conditional assumptions. Charge-reference uncertainty is retained separately; total physical and post-ISP uncertainty remain unknown. Results do not authenticate supplied calibration documents or establish EMVA compliance.

The distinction between total temporal noise and model-specific noise separation follows the scope caution in [EMVA 1288 Release 4.0 General](https://www.emva.org/wp-content/uploads/EMVA1288General_4.0Release.pdf). The implemented estimator is its own named method, not an implementation of that standard.

## Original observation records

New collection `readout_observations`, schema `camera_readout_fit_observations_v1`. Metadata extends common Provenance with `name`, `revision`, `capture_id`, `dataset_role` (development/holdout), `dataset_ids`, `roi` (`row_range` and `column_range`, full native coordinates, end-exclusive), `charge_statistics` fixed to `poisson_total_pre_full_well`, `charge_reference` using the existing AbsoluteChargeReference contract, and `frames`: ordered `{frame_id, mean_total_charge_e: [R,Gr,Gb,B]}`. All capture frames are mapped exactly once, including paired paths sharing one charge target. The even ROI is inside the retained native crop. Capture settings must be recorded applied; CFA is RGGB. Target means are finite and nonnegative. The externally supplied calibration declaration must cover the selected charge quantities; source labels do not authenticate that claim.

Import metadata JSON and reference-evidence JSON as original bytes. Evidence uses the existing charge-reference evidence document contract. Retain the capture snapshot/hash and exact source closure; revalidate every read. Observation lineage includes capture/frame/group/parent tokens plus declared observation dataset IDs. Two target files describing the same RAW cannot establish independence.

Module `readout_fit_contracts.py` defines observation/import, fitting request and publish contracts. Module `readout_observations.py` provides `import_observations(service, metadata, evidence_bytes, *, metadata_bytes=None)`, `get(service,id)`, `lineage(service,record)`, `groups(service,record)` and `template(service,capture_id)`.

`groups` returns a list of `{mean_charge_e: float, raw_dn: ndarray[N,P]}` plus binding metadata; group pixels by exact declared target and path count, never approximate their values. Fixed electronics apply across selected native sites; stationary/Poisson/uniform-within-site assumptions remain explicit. Training requires low-charge repetitions and enough covered charge levels to identify the fixed knot grid.

Admission also checks each total input mean against the largest expected dark charge in that frame's selected CFA sites. A lower mean would imply negative photocharge under the retained dark model and is refused. Only an eight-epsilon relative arithmetic tolerance applies; it is not a physical uncertainty allowance. Dark charge is not added to these total means a second time.

## Fitting job and immutable publication

`camera_readout_fit_request_v1`: `name`, `base_calibration_id`, `training_observation_ids`, `validation_observation_ids`, `slope_scale_bounds`, `sigma_v_bounds`, `max_iterations`. Training and validation lists are explicit and nonempty. Request, snapshots, original evidence, roles, lineage, source environment and resource forecast are frozen before submission. The job kind is `readout_fit`; heavy fitting/evaluation runs only in the existing supervised Worker.

Worker execution emits candidate metadata and numerical diagnostics as artifacts. It does not publish a usable response calibration. Explicit publication of a succeeded job requires its pinned request/result hashes plus requested name/revision. A short atomic transaction rechecks job and input record rows, then publishes one deterministic immutable record with artifact ownership and audit. Retries return that same record. Cancellation, failed or changed jobs cannot publish.

New fitted response schema `camera_fitted_response_calibration_v1` lives in `readout_calibrations` and has its own verifier. Imported v1 calibration metadata, exact three artifacts, source dictionaries and historical cache keys remain unchanged. The fitted verifier exposes the same common electrical/dark/native fields to replay while adding the fit request/result and training/evaluation evidence closure. `reference_capture_ids` names training captures only. Evaluation identities are separately marked development-used and excluded from later independent Study claims without pretending they were fitting inputs.

## Integration and acceptance

Public API/SDK and Workbench must support observation import, plan, Worker submission, saved diagnostics, explicit candidate publication, and use of the fitted response for imported RAW replay. Bundle/backup closures must include original targets, RAW, calibration parents and fit/evaluation evidence. Preserve dev12 bytes and old run-only contracts.

Acceptance requires independent authored forward fixtures, numerical recovery and held-out distributions, malformed/unanchored/unsupported/overlapping-data refusals, publication idempotency and race checks, actual HTTP/Worker/browser paths, original bytes, restart and backup/restore. Synthetic fixtures remain simulated; actual physical measurement count stays zero unless authentic user data is supplied.


## Qualified dev13 evidence

The full platform suite passed **3,627 tests**; Node screen-logic checks passed **170 tests** (mock DOM, separate from actual-browser checks). The numerical kernel has independent authored forward fixtures and gradient/quantizer/refusal coverage. HTTP/Worker qualification passed **1,004 checks**, with two fitting/publication jobs and three fresh single/HCG/LCG replays, 32 saved JSON records, 180 unique public artifacts and five graph bundles containing 682 exact members. The browser separately uploaded exact metadata/evidence bytes, fitted, inspected diagnostics, published and selected that revision for retained RAW replay; it did not execute an additional browser replay.

The authored single-path noise scale was 0.005 V and the fitted scale was 0.00501965 V. This is numerical recovery for a declared small-capacity fixture. It is not a physical accuracy estimate. DCG covariance uses inherited correlation and separately fitted marginal scales. The holdout evaluation is conditional on the declared charge means and fixed electronics; it does not propagate charge-anchor uncertainty through a full physical model.

A dedicated QA runtime was restarted and checked using separate readback evidence. Its backup was restored into a new directory with exact logical rows and reachable blob bytes. The dev12 subset (73 records, 29 jobs, 160 audit rows and 1,268 blobs) and six historical bundles (923 members) remained unchanged. Initial verification-tool failures were preserved and corrected in new reports: the HTTP tool assumed a legacy ZIP artifact layout and the legacy tool compared pretty-printed JSON byte pins to canonical JSON. A resumed journal reused 13 already acknowledged responses without resending POSTs.
