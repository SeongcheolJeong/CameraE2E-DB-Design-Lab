# Camera Platform — 수치 지표 Surrogate

Surrogate Prediction의 첫 연결 범위는 **고정 카메라·시험·기준 계산기의 수치 지표**다.
완료된 설계 실험 → 학습/검증 조건 선택 → 별도 Worker의 모델 생성 → 수치 오차 비교 →
허용 범위 내 일괄 예측 → 근거 보존을 UI, HTTP API, Python SDK에서 사용할 수 있다.

원문의 일곱 모듈·네 실행 방식 전체가 완료된 것은 아니다. 이 모델은 Lens/Sensor 부품
응답 자산을 대체하는 일반 모델이 아니며, RAW/RGB 영상·3D 장면·폐루프 제어를 예측하지 않는다.
기존 models와 별도로 surrogates에서 학습 작업과 결과를 관리한다.

## 학습과 적용 범위

- 입력은 설계 변수 탐색의 일곱 변수 중 1–6개, 출력은 지원 지표 중 1–4개다.
  UI는 한 학습 실험·한 검증 실험·한 출력부터 선택하며, API/SDK는 여러 실험을 합칠 수 있다.
- 모든 선택 Run은 성공 상태이며 동일한 기준 Camera Assembly/Test, 변수·단위,
  기준 Runtime·실행 환경·Seed·프레임·출력 크기를 사용해야 한다.
- 학습은 차원 수 + 2~192개, 검증은 max(3, 차원 수 + 1)~64개 조건이다.
  검증은 각 입력 축에서 변화가 있어야 한다.
- 학습 입력의 최소·최대로 정의한 상자 영역의 **모든 모서리 조합**이 학습 데이터에 있어야 한다.
  2차원 OAT 십자 형태만으로 상자 전체의 사용을 허용하지 않는다.
- 정규화 좌표 거리 1e-8 이하인 중복·근접 조건은 두 집합 내부 및 집합 간 모두 거부한다.
  같은 기준점의 새 Run ID도 별도 검증 근거로 인정하지 않는다.
- 새 모델은 같은 원본 구성의 수치 지표를 근사한다. 학습하지 않은 변수, 다른 부품 버전,
  다른 시험, 범위 밖 입력, 잘못된 단위는 기존 모델의 지원 범위가 아니다.
- 이전 환경의 계산 자료도 한 모델의 모든 기준 데이터가 그 환경으로 일치하면 사용할 수 있다.
  **기준 데이터의 환경과 학습/추론 실행 환경을 각각 기록**한다.

모든 모서리가 존재한다는 조건은 학습 범위가 지지되는지를 확인한다. 그 영역 전체에서
일정 오차 이하라는 보장은 아니다. 검증 조건의 실제 최소·최대도 화면에 따로 표시한다.

## 계산 방법과 수치 검증

normalized_thin_plate_rbf_linear_tail/1은 정규화 입력에 thin-plate spline RBF와
1차 다항식 항을 사용한다. 계수는 학습 데이터로만 계산한다. 커널 설정은 고정이며
검증 자료로 하이퍼파라미터를 조정하지 않는다. 입력 범위와 출력 평균·범위도 학습에서만 얻는다.

블록 방정식은 [SciPy 공식 RBFInterpolator 설명](https://docs.scipy.org/doc/scipy/reference/generated/scipy.interpolate.RBFInterpolator.html)에 따른다.
설치된 SciPy와 1·2·3·6차원 비선형/선형 출력의 예측을 독립 비교하고, JSON 저장 후
계수가 동일하게 작동하는 것을 시험한다. 모델은 Python pickle이나 라이브러리의 비공개
인스턴스 상태를 저장하지 않는다. 조건수가 1e12를 넘는 학습 문제는 거부한다.

학습 계획에는 출력별 단위와 **최대 절대 오차 허용값**을 미리 고정한다.
검증 결과는 조건별 기준값·예측값·부호 있는 잔차, 관측 최대 절대 오차와 RMSE를 보존한다.
허용 오차 초과 또는 허용되지 않는 음수 광전자 등의 출력이면 학습 작업은 완료되어도
수치 검증은 FAIL이며 예측 사용이 차단된다. 실패 결과를 지우거나 허용값을 자동 완화하지 않는다.

검증 자료가 이전 모델에서도 쓰였다면 원본 Run과 해당 모델의 참조를 보존한다.
이 분리는 **해당 학습에서 입력 조건이 겹치지 않는다는 의미**다. 자료가 비공개이거나,
이전 반복 조정과 독립이거나, 독립 실물 측정이라는 주장은 하지 않는다.

승인 상태는 candidate, 실물 검증은 not_established, 전체 불확실도는 unknown을 유지한다.
관측 최대 오차를 전체 영역의 절대 경계나 실물 예측 불확실도로 바꾸지 않는다.
원본 입력 경계의 조건부 전파도 이 근사 모델에서는 추가로 확립되지 않았다.

## 재현성과 실행

계획 미리보기는 데이터를 쓰지 않는다. 제출은 계획·기준 Run의 입력/결과 해시·학습 환경을
재검사하고 기존 Queue에 하나의 불변 작업을 저장한다. 같은 계획의 재제출은 기존 작업을
재사용한다. Worker는 실제 실행 전에도 환경과 원본 증거를 확인한다.

결과는 학습된 계수·스케일·영역·원본 Study/Run 해시·카메라/시험 맥락·오차 기준·검증
잔차를 포함한다. 성공한 작업의 결과는 기존 Registry의 불변 트리거와 Audit 해시로 보호한다.
빠른 추론은 저장한 계수를 사용하며 매번 재학습하거나 기준 카메라를 재실행하지 않는다.

일괄 예측은 최대 4,096개 조건이며 하나라도 범위 밖이면 전체 요청을 거부한다.
예측 입력, 결과, 사용 모델 입력/결과 해시, 참조 계산 환경, 실제 추론 환경을
surrogate_predictions에 보존한다. API 비용과 원본 조회·영속 저장 비용은 존재한다.

- GET /api/v1/surrogates/catalog
- POST /api/v1/surrogates/plan
- POST /api/v1/surrogates
- GET /api/v1/surrogates 및 GET /api/v1/surrogates/{id}
- POST /api/v1/surrogates/{id}/predict
- GET /api/v1/surrogate_predictions/{id}

SDK는 plan_surrogate, submit_surrogate, wait_surrogate, predict_surrogate를 제공한다.
시간 초과는 완료로 처리하지 않으며 기존 ID로 대기를 재개한다.
UI의 JSON Export는 모델과 검증, 또는 모든 예측을 포함한다. 전체 참조 RAW 파일까지
자급하는 통합 실행 패키지는 별도 후속 범위다.

## 검증 경로와 남은 범위

tests/platform/test_surrogates.py는 독립 SciPy 비교, 원본 분리·조건 일치,
불변 저장·재오픈, 허용 오차 실패, 범위/단위 거부, HTTP 계약을 확인한다.

tools/verify_camera_surrogate.py는 실제 API/Worker로 16개 학습 조합과 별도 9개
검증 조건을 계산하고, 학습·검증·1,024개 일괄 예측·저장·범위 거부를 확인한다.
tools/verify_camera_surrogate_ui.cjs는 실제 브라우저의 조건 선택, 중복 기준점 제외 표시,
계획 변경 무효화, 학습·오차·추론·JSON Export·재오픈·모바일 배치를 확인한다.
tools/verify_camera_package.py도 Checkout 외부 설치 코드로 같은 모델 생성과 예측을 검사한다.

속도 보고서는 실제 반복 측정값을 보존한다. 기준 경로는 RAW/RGB를 포함한 Response-DB
계산이고 Surrogate는 선택한 수치만 반환한다. 커널 비교에서는 양쪽의 HTTP/Queue/원본
조회/영속 저장을 제외하고, 전체 추론 API 시간은 따로 기록한다. 보편적 속도 보장은 아니다.

후속은 일반 광학/픽셀/전기/ISP 변수와 영상·응답 함수 Surrogate, 적응형 추가 계산,
연속 영역의 오차/불확실도 모델, 다목적 최적화, 독립 실측 검증, 일반 Composer/모델
승인·배포 연결이다. 계수 모델을 만든 것만으로 이 범위가 완료되지는 않는다.


## 확인된 운영 후속 과제

기본 작업실의 50개 Camera Run에서 전체 bootstrap 응답이 11,428,639 bytes인 것을
[별도 관측](../reports/camera_platform/bootstrap-growth-observation.json)으로 확인했다.
수치 추론 속도와 화면 초기 로딩 비용은 다르다. 전체 근거 API를 유지하면서 작업실 목록의
명시적 요약과 선택한 기록의 상세 로딩을 분리하는 작업이 다음 우선순위다.
아주 작은 비영(非零) 잔차는 현재 화면의 소수점 8자리에서 0으로 반올림된다.
전체 JSON의 실제 값은 보존되며, 다음 화면 개선에서 과학적 표기로 구분한다.
