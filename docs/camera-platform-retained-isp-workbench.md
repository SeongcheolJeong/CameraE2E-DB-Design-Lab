# 잔류 RAW ISP의 통합 목록 조회

0.16.1.dev2 개발 소스는 ISP 작업실의 원본·모델·재처리·후보 비교 목록을
`GET /api/v1/retained-isp/workbench` 한 번으로 가져온다. 기본 앱 0.15.0과
독립 설치 후보 0.16.0에는 아직 이 변경을 적용하지 않았다.

기존 화면은 네 요청에서 전체 작업 이력을 반복 복원하고, 사용하지 않는 모델과
상세 결과도 내려받았다. 새 경로는 현재 호출 안에서 작업 이력과 완료 감사 증거를
한 번 검증한 뒤 목록을 만든다. 모든 모델도 검증한 후 잔류 RAW용 ISP만 선택한다.

## 화면과 증거의 경계

응답 스키마는 `camera_retained_isp_workbench_v1`이다. 원본 선택지는 기존과 같은
메타데이터이며 원본 RAW 바이트 검증 완료를 뜻하지 않는다. 화면에 이 범위를 표시하고,
초안 생성·실행 준비에서는 원본을 다시 읽어 검증한다.

모델에는 후보 초안 작성에 필요한 전체 ISP 처리 설정을 포함한다. 작업 이력에는
이름·상태·원본 선택·모델 식별자·전체 상세 기록의 SHA-256·상세 조회 경로를 담고,
큰 고정 입력이나 프레임 결과 배열은 담지 않는다. 저장 재처리·후보 비교는 기존
도메인 검증을 실행하며 원본·출력·미리보기 바이트 검사를 생략하지 않는다.

사용자가 이력에서 결과를 선택하면 기존 상세 GET으로 다시 확인한다. 프레임별 지표,
PNG와 근거 ZIP은 그 상세 결과에 연결된다. 목록 요약을 실제 결과로 표시하지 않는다.
UI는 불완전하거나 다른 스키마인 응답을 거부하며 예전 네 요청으로 우회하지 않는다.
늦게 끝난 과거 목록 요청은 최신 목록을 바꾸지 못한다. 조회 실패 시 이전 영상은
지우되 사용자가 편집한 초안은 유지한다.

## 일관성과 크기 제한

작업과 완료 이벤트는 Registry의 같은 읽기 스냅샷을 사용한다. 모델은 별도의 기록
스냅샷이며 연결 파일은 검증 시점에 다시 읽는다. 전체 DB와 파일 시스템이 하나의
원자적 스냅샷이라는 보장은 없다. 호출 간 캐시나 검증 전 필터는 없다. 내부 재사용
객체는 반환하지 않으며 필요한 값은 분리해서 복사한다.

직렬화 응답은 4 MiB로 제한한다. 한도를 넘으면 명시적으로 실패하며 일부 이력을
조용히 누락하지 않는다. 전체 작업 이력을 복원하는 비용과 메모리 증가 문제는 남아
있으므로 이 변경을 전체 규모 확장 완료로 해석하지 않는다.

## 검증 범위

새 통합 조회와 기존 원본·재처리·비교의 Python 시험 110개, 실제 UI 모듈의 Node
시험 35개가 통과했다. 관련 없는 손상된 작업·모델, 같은 크기로 바뀐 RAW·출력·PNG,
완료 이벤트 변경, 호출 간 참조 공유, 응답 한도, 늦은 응답과 초안 보존을 포함한다.

[백엔드 검사](../reports/camera_platform/retained-isp-workbench-v0161/source-verification.json),
[화면 로직 검사](../reports/camera_platform/retained-isp-workbench-v0161/ui-final-verification.json),
[설계 검토](../reports/camera_platform/retained-isp-workbench-v0161/contract-review.md).

137개 기록·77개 작업·2,388개 Blob을 복사한 상태에서 이전 네 응답은 총
26,632,352바이트, 새 응답은 49,315바이트였다. 선택지 25개·모델 8개·재처리 14개·비교
4개의 표시값과 전체 상세 해시가 같았다. 세 쌍의 오프라인 처리 중앙값은
18.19→8.59초, 최대 RSS의 중앙값은 약 375→362 MB였다. 전체 이력의 메모리 비용은
여전히 크다. 이전 dev1 중복 제거도 포함한 현재 소스와 설치 v0.16의 비교이며,
통합 조회 한 변경만의 인과적 효과를 따로 측정한 값은 아니다.

첫 이전 버전 측정과 독립 시험이 일부 겹쳤고 모든 시도를 그대로 보존했다.
나머지 두 쌍은 해당 시험 종료 후 실행했다. OS 전체 부하를 격리하지 않았으며
브라우저의 기존 병렬 요청과 다른 순차 측정이므로 HTTP 지연 개선율로 사용하지 않는다.
[측정 결과와 조건](../reports/camera_platform/retained-isp-workbench-v0161/benchmark-results.md),
[최종 측정 증거](../reports/camera_platform/retained-isp-workbench-v0161/benchmark-final-proof.json)를 따른다.

실제 별도 소스 API에서 단일 조회와 두 동시 조회의 응답이 오프라인 결과와 정확히
같았고, 선택한 재처리·비교 상세도 이전 전체 기록과 같았다. 단일 조회는 9.76초,
두 요청 완료까지는 20.46초였다. 동시 사용 시 지연과 전체 이력 메모리 비용은 남는다.
실제 브라우저에서 25개 원본·8개 모델·18개 이력, 여섯 번째 후보의 세 번째 프레임을
확인했다. 두 PNG가 8×8로 로드됐고 왜곡·공간·시간 지표와 근거 ZIP 연결이 일치했다.
이 브라우저 검사에서는 새 계산이나 ZIP 다운로드를 수행하지 않았다.
